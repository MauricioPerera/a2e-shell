# Catalog

The catalog is an optional layer that gives a session **curated, versioned, discoverable content** from a git repo without bloating the HTTP API with content-type-specific endpoints.

A catalog consists of two git refs (default branches `index` and `main`) materialized into the session's filesystem, plus a precomputed reachability report.

## Mental model

```
session/
├── catalog/
│   ├── index/              ← worktree of `index` branch (manifest + partitions)
│   │   ├── manifest.json
│   │   ├── skills.json
│   │   ├── docs.json
│   │   ├── prompts.json
│   │   └── templates.json
│   ├── content/            ← worktree of `main` branch (actual files)
│   │   ├── skills/
│   │   ├── docs/
│   │   ├── prompts/
│   │   └── templates/
│   └── reachability.json   ← precomputed at session create
└── transcript.jsonl
```

The LLM discovers via `$A2E_CATALOG_INDEX`, hydrates via `$A2E_CATALOG_CONTENT`, filters via `$A2E_CATALOG_REACHABILITY`. All three are env vars injected into every exec subprocess.

## Request shape

```json
{
  "catalog": {
    "repo_url": "https://github.com/org/knowledge",
    "index_ref": "index",
    "content_ref": "main",
    "auth": { "type": "token", "env_var": "GITHUB_TOKEN" }
  }
}
```

### `repo_url` formats

| Scheme | Example | Auth |
|---|---|---|
| `https://` | `https://github.com/org/repo` | optional `token` |
| `ssh://` | `ssh://git@github.com/org/repo` | `ssh_key` |
| `git@` | `git@github.com:org/repo.git` | `ssh_key` |
| `file://` | `file:///srv/repos/knowledge` | none |

### `index_ref` / `content_ref`

Accepts **branch, tag, or 40-hex SHA**. The server detects SHAs by regex and uses a different clone path (`git init + fetch --depth=1 <sha> + checkout --detach`).

- **Branch/tag** → refetched if cache is older than `A2E_CATALOG_CACHE_REFRESH_S` (default 60s).
- **SHA** → immutable; never re-fetched after first resolution.

## The index branch

An **orphan branch** with no shared history with content. Contains only manifests generated by CI.

`manifest.json` at the root:

```json
{
  "schema_version": "1.0",
  "source_sha": "e79a89...",           // the content commit this index was built from
  "source_branch": "main",
  "generated_at": "2026-04-19T02:30:00Z",
  "categories": {
    "skills":    { "path": "skills.json",    "count": 12, "bytes": 4820, "sha256": "..." },
    "docs":      { "path": "docs.json",      "count": 28, "bytes": 18340, "sha256": "..." },
    "prompts":   { "path": "prompts.json",   "count": 4,  "bytes": 1200,  "sha256": "..." },
    "templates": { "path": "templates.json", "count": 5,  "bytes": 1870,  "sha256": "..." }
  }
}
```

Each partition (`skills.json`, etc.) contains:

```json
{
  "schema_version": "1.0",
  "category": "skills",
  "entries": {
    "refund-order": {
      "name": "refund-order",
      "when_to_use": "user asks to cancel or refund an order",
      "description": "...",
      "skill_path": "skills/refund-order",
      "entry": "run.sh",
      "entry_path": "skills/refund-order/run.sh",
      "entry_sha": "3962d0...",         // git blob SHA of the executable
      "entry_bytes": 158,
      "estimated_tokens": 40,
      "args": [
        { "name": "order_id", "type": "string", "required": true, "description": "..." }
      ],
      "requires": ["curl", "jq"]
    }
  }
}
```

Full schema: [a2e-skills/INDEX-SCHEMA.json](../../a2e-skills/INDEX-SCHEMA.json).

## `in_sync` flag

`CatalogInfo.in_sync` is `true` iff `content_sha === manifest.source_sha`. Meaning:

- **`in_sync: true`** — the index was generated from exactly this commit of content. Safe to trust that `entry_path` files exist with `entry_sha` SHAs.
- **`in_sync: false`** — you pinned content and index to different commits. The index may list entries whose content paths don't exist (false positives) or miss newer entries. The LLM can still navigate, but hydration may fail. Verify via `ls $A2E_CATALOG_CONTENT/skills/` before trusting the catalog view.

Common case: pinning content to a tag (`v0.1.0`) while index is at HEAD → `in_sync: false` because index reflects newer source code.

## Reachability

At session bootstrap, after cloning both refs, the server computes a **reachability report** cross-referencing each skill's `requires` array against the session's `binaries_allowlist`:

```json
{
  "schema_version": "1.0",
  "computed_at": "2026-04-19T02:30:00Z",
  "by_category": {
    "skills": {
      "refund-order": { "reachable": true },
      "deploy-service": { "reachable": false, "missing_binaries": ["kubectl"] }
    },
    "docs": { "stripe-api": { "reachable": true } },
    "prompts": {...},
    "templates": {...}
  },
  "summary": { "total": 47, "reachable": 44, "unreachable": 3 }
}
```

Non-skill categories (docs/prompts/templates) are always reachable — they're passive content with no execution requirements.

The LLM is expected to filter by reachability before invoking skills:

```bash
jq '.by_category.skills | to_entries | map(select(.value.reachable)) | from_entries' \
  < $A2E_CATALOG_REACHABILITY
```

## Pinning — the four modes

| `index_ref` | `content_ref` | Behavior | Use case |
|---|---|---|---|
| `"index"` | `"main"` (default) | Both follow branch HEAD; branch refetch every 60s | Normal dev |
| `"v1.0.0"` tag | `"v1.0.0"` tag | Both pinned to tagged release | Production deploys |
| 40-hex SHA | 40-hex SHA | Both pinned to immutable commits | Reproducible audit, A/B testing |
| `"index"` HEAD | specific SHA | Index sees newest entries; content at old SHA | Rollback workflows (detect via `in_sync: false`) |

## Shared cache

When `A2E_CATALOG_CACHE_ENABLED=true` (default), one bare mirror per `repo_url` is shared across all sessions. Sessions receive **git worktrees** pointing at their requested SHA — worktrees share the mirror's object database, so disk per session is ~the size of the checked-out files only.

```
<cache_dir>/
└── <sha256(repo_url) truncated>/
    └── mirror.git/              ← bare clone, all branches and tags
        └── worktrees/           ← git metadata referencing per-session worktrees
```

Concurrency: multiple simultaneous sessions for the same repo collapse to a single network fetch via an in-flight promise map.

Partial clone: mirror is cloned with `--filter=blob:none` when `A2E_CATALOG_CACHE_FILTER_BLOBS=true`. Blobs hydrate on demand via the promisor remote when worktrees check out files.

## Credential flow (repeat with emphasis)

The client **never transmits credentials**. It names env vars on the server:

```json
{ "auth": { "type": "token", "env_var": "GITHUB_TOKEN" } }
```

The server:

1. Resolves `process.env.GITHUB_TOKEN` at session create.
2. Throws `CAPABILITY_DENIED` if unset.
3. Adds the token value to the session's redactor (auto).
4. Injects it as `Authorization: Basic` via `-c http.extraheader` for every git call.
5. The token value is scrubbed from any output before it reaches transcripts or HTTP responses.

Same for `ssh_key`: the env var holds the **path** to a key file, the server validates existence, injects `GIT_SSH_COMMAND`, never surfaces the path to the LLM (though paths aren't typically secret).

## Authoring a catalog repo

See [a2e-skills/CONVENTION.md](../../a2e-skills/CONVENTION.md) for the authoring rules (frontmatter, directory layout, CI-regenerated index branch).

The typical setup:

1. Commit skills/docs/prompts/templates under their category directories with frontmatter.
2. CI runs the generator on every push to content branches, force-pushes to the orphan `index` branch.
3. Agents consume `index` as their source of truth for discovery, `main` (or pinned ref) as content.

## Operational pitfalls

- **Stale index window**: CI takes N minutes to regenerate after a content push. Agents creating sessions during that window see `in_sync: false`. This is normal; `in_sync` is the signal to handle it.
- **Orphan branch requires `git push --force`**: a bot-specific PAT with push permission on the `index` branch only is safer than a generic write token.
- **Cache grows unbounded**: no LRU in v1. Prune by wiping `<cache_dir>/<repo-hash>/` for any mirror you're done with.
- **Worktree prune is lazy**: when a session is deleted, its worktrees are `rm -rf`'d but the mirror's `git worktree list` retains stale entries until `git worktree prune` runs. The server runs prune fire-and-forget on session delete; periodic cron is defense in depth.
- **ssh_key auth + cache sharing**: the cache mirror is created with the first session's auth. A later session without SSH auth will use the cached mirror as-is — no re-auth check. If auth must be per-session enforced at each access, disable the shared cache (`A2E_CATALOG_CACHE_ENABLED=false`). Trade-off: every session pays full clone cost.
